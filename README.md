# ムササビシュート

ハンドボールの **ムササビシュート（プロンジョンシュート）** をテーマにした3Dブラウザゲームです。
画面右のサイドの選手（右利き・背番号7）を操作し、走りながらパスを受けて、3歩以内に跳んでシュートを決めます。1ゲームは20本です。

画面は **選手の背中越しの3D視点**。選手の作り・質感・操作ボタン・ナビは
techgymjp/center-fly（センターフライ）、techgymjp/jackal（ジャッカル）、techgymjp/corner-kick（コーナーキック）と揃えています。
会場は **室内のハンドボール競技場** です（木の床、青いゴールエリア、近くて急なスタンド、天井の照明、大型ビジョン）。

`index.html` をブラウザで開くだけで遊べます（Web 版はビルド不要）。Android アプリ版もあります（下記）。3D描画に同梱の three.js（`vendor/three.min.js`, MIT License）を使っています。
GitHub Pages などの静的ホスティングにそのまま置けます。

## ムササビシュートとは

サイドの選手が、**ゴールではなくコート中央側へ跳び込み**、空中で体を大きく倒してシュートの角度を広げる技です。

- 1969年の全日本のヨーロッパ遠征で「ノダ・シュート」と呼ばれ、1971年に日本のマスコミが、木から木へ飛び移るムササビの姿に重ねて「むささびシュート」と呼んだのが名前の由来とされています。
- 右利きは **左足で踏み切る**。
- **まず高く跳んで、空中でキーパーの動きを見る**。最初から体を倒しすぎると上のコースが打てなくなる。滞空の後半で体を大きく広げて倒す。
- ボールは頭の近くに構える。
- 着地は手足で受け、背中の方へ転がるように逃がす（シュートを打った後ならゴールエリアの中に倒れ込んでよい）。

ゲームではこれを次のように再現しています。

| 実際の技 | ゲーム |
| --- | --- |
| コート中央側へ跳ぶ | ムササビはゴールではなく中央へ跳び、ゴールエリアの上を横切る |
| 左足で踏み切る | 3歩目（左足）で踏み切ると自然な形（ムササビには受けてからダッシュで2歩が必要） |
| 高く跳んでキーパーを見る | 跳んだ直後は体を起こしたまま。キーパーの動き（吹き出し）を見てから打てる |
| 後半で体を倒して角度を広げる | 滞空の後半で手足を広げて体が倒れていく。倒れるほどボールの位置が中央へ寄ってゴールが広く見える（コースのぶれが減る） |
| 倒しすぎると上が打てない | 体が倒れるほど高いコースに届かなくなる |
| 手足で着地して転がる | ムササビの後は手足から着地して転がる |
| 滞空時間が長い | ふつうのジャンプの約2倍 |

## サイドの位置取り（調べたこと）

- サイドはゴール左右のコーナー寄りに位置取る
- ボールが来てから走ってはディフェンスに寄られるので、来る前に助走して **走り込みながら受ける**。受けてからは2〜3歩で跳ぶ
- サイドラインに沿って走り、曲線を描いてセンターへ寄ることで角度を作る
- プロンジョンはゴールエリアラインぎりぎりで踏み切り、ほぼ真横（コート中央方向）へ跳ぶ。右利きは画面右のサイドから左へ跳び、左足で踏み切って左手足で着地する

## 大きさ

実物どおりの寸法です: ゴール 幅3m×高さ2m、ゴールエリア（6mライン）、フリースローライン（9m）、コート 40m×20m、選手の身長 約1.85m、ボール 直径約19cm（見やすさのため少し大きめ）。
カメラは選手のすぐ後ろ（約2.6m）から、実際の見え方に近い画角で映します。踏み切りは6mラインの約1m外側になります。

## 1本の流れ

0. **ホイッスル** — 「◯本目」と開始位置・キーパーのタイプが出て、選手が構えて待ちます。レフリーの短いホイッスル「ピッ！」でプレー開始。
1. **パスを受ける** — ホイッスルと同時に走り出し、味方（10番）からパスを受けます。パスは **直接パス・バウンドパス・山なりパス** のどれか。
   開始位置は次のどれかで、毎回少しずつ変わります（キーパーのタイプも毎回変わります）。
   - **右コーナーから** — ゴールライン際から上がって受ける。角度がないので早めに跳ぶ
   - **サイドの定位置から** — 中央へ切れ込んで受ける
   - **サイドライン沿いに走り込んで** — サイドラインに沿って走り、曲線を描いてセンターへ寄る
2. **3歩以内に跳ぶ** — 受けたところから歩数を数えます（足あとに 1・2・3）。左（ゴール中央の方）へ切れ込みながら、
   - **ジャンプ** はいつでも跳べる
   - **パスを受けてからダッシュで2歩踏むと**、ジャンプボタンが自動で **ムササビ** に切り替わる（ダッシュボタンのまわりの目盛りが踏んだ歩数）。
     パスを受けるまでは操作なし（走る速さは開始位置で決まる初期条件。サイドライン沿いは勢いよく走り込み、コーナー・定位置はゆっくり）
3. **着地するまでにシュート** — ノーマル・ループ・左スピン・右スピン・バウンドのどれか。跳ばずに打つとステップシュート。

失敗: 4歩目を踏む（オーバーステップ）、6mラインを踏む（ラインクロス）、シュートを打つ前・投げ終わる前に着地する。

## 操作

| 操作 | タッチ / マウス | キーボード |
| --- | --- | --- |
| シュートのコース（左右・高低） | 跳んだら左端に出る **方向キー（方角リング）**（16方位） | 矢印キー / WASD |
| ジャンプ / ムササビ（受けてからダッシュで2歩踏むと自動でムササビ。跳ぶまでそのまま） | 左端の **上**（地上のとき） | Space / Z |
| ノーマル | ひし形の **まん中** | U |
| ループ | ひし形の **上** | I |
| 左スピン | ひし形の **左** | J |
| 右スピン | ひし形の **右** | L |
| バウンド | ひし形の **下** | K |
| ダッシュ | 左端の **下**（長押し・地上のとき） | Shift |
| 一時停止 | — | P / Esc |
| 音のオン/オフ | 画面上部のスピーカーボタン | M |
| ナビのオン/オフ | 画面上部の「ナビ」ボタン | N |

左端は地上ではジャンプとダッシュ、跳ぶと自動で方向キー（方角リング）に切り替わります（押していた指をそのまま滑らせても方向キーになる）。
シュートのひし形は右端です。助走のコースは自動で、方向キーでは変えません。
シュートボタンは地上でも押せます（ステップシュート。方向が入っていなければファーの低めを狙う）。

- **ダッシュ** — 押している間は **歩幅が大きく** なって速く走る（ふつう約0.9m → ダッシュ約1.6m。前傾して、画面の左右に流れる線が出る）。
  受けてからダッシュで2歩踏むとムササビになり、一度なったら離しても跳ぶまでムササビのまま。
  「ダッシュ2歩でそのまま跳ぶ」か「ダッシュ2歩 → 離して3歩目を小さく踏んで跳ぶ」。ダッシュのまま3歩踏むとラインに入りやすい
- **6mラインとの駆け引き** — 助走は6mラインに向かって切れ込む。ダッシュのまま3歩進むと、3歩目でラインに入りやすい。
  ダッシュ2歩でムササビにしたら、そのまま跳ぶか、ダッシュを離して小さい歩幅で合わせよう

- **ジャンプには踏ん張りがある** — 押すとまず踏み切り足で床を踏んで沈み込み（約0.12秒、ムササビは約0.16秒）、それから跳ぶ。踏ん張っている間も前へ進むので、6mラインの直前で押すと踏んでしまう
- **投げるのに時間がかかる** — シュートボタンを押すと腕を後ろへ引いてから振り抜き、約0.25〜0.3秒後にボールが手を離れる（ノーマル・バウンドは短め、ループ・スピンは長め）。
  コースはリリースの瞬間の方角リングで決まる。**投げ終わる前に着地すると失敗**

### シュートの種類（ボタン × タイミング × 方向）

| ボタン | 球筋 | 基本点 |
| --- | --- | --- |
| ノーマル | 速い直球。方角リングの通りに飛ぶ | 100 |
| ループ | キーパーの頭上を越える山なりのボール。キーパーは下がりながらジャンプして手を伸ばすので、まん中は止められやすい。隅を狙う | 150 |
| 左スピン / 右スピン | 逆側を狙うように見せて、床でバウンドしてから左 / 右へ切れる。**助走のスピード（ダッシュ）と歩数が多いほどキレる**（オレンジの軌跡と「キュッ！ キレ強」で分かる） | 180 |
| バウンド | 床に当てて足元を抜く | 130 |

| 打つタイミング | 倍率 |
| --- | --- |
| ステップ（跳ばずに打つ） | ×1.0 |
| クイック（跳んですぐ） | ×1.3 |
| ジャンプ（頂点あたり） | ×1.2 |
| 倒れ込み（落ちながら） | ×1.1 |
| ムササビ | ×2.0 |

ゴールの隅に決めると +50、連続ゴールでボーナス。ムササビで打った瞬間はスローモーションになります。

### ゴールキーパー

キーパーはシューターの方を向き、シューターとゴール（ニア寄り）を結ぶ線の上へ前に詰めて角度を消します。
シューターが近づくほど、跳んだらさらに前へ出ます（どれだけ出るかはタイプで違う）。シュートが放たれた後は、その場から左右・上下に反応します。

タイプ（定位置でじっくり型・飛び出し型・ニアを固める型・左右に揺さぶる型・フェイント型・ゴールライン型・大の字ジャンプ型）ごとに、立つ位置と動き方が違います。
シューターが空中にいる間、キーパーは先に動くことがあり、吹き出しで表示されます。

- 「前に出てきた！」「しゃがんだ！」「両手を広げた！」 → ループ
- 「大の字ジャンプ！」 → バウンド
- 「左に倒れた！」「右に倒れた！」 → 逆サイドへノーマル

セーブすると両手を上げて喜び、決められるとうなだれます。

### ナビ

ナビ ON（初期設定）のとき:

- 次の1歩で6mラインに入るときや3歩目に「跳べ！」と出て、ジャンプボタンと6mラインが光る
- パスを受けたあとダッシュしていなければ、ダッシュボタンが点滅する（ムササビの準備）
- キーパーが先に動いたら、効くシュートのボタンが点滅する

## 画面

- **タイトル** — スタート・遊び方・ベスト記録・言語の切り替え（日本語 / English）
- **遊び方** — 操作説明は別画面。タイトルの「遊び方」から開き、「もどる」で戻る
- **結果** — 称号（S〜D）・得点・20本の記録と、シェア

## シェア

結果画面の「📤 結果をシェア」から、成績画像（1200×630）つきでシェアできます（対応していない環境ではコピー）。
「𝕏 ポスト」「LINE」「コピー」ボタンもあります。シェア文には紹介記事 https://techgym.jp/column/claude-code-game-plongeonshoot/ が入ります。

## 言語

日本語と英語に対応しています。端末の言語が日本語なら日本語、それ以外は英語で表示し、タイトル画面のボタンで切り替えられます（選んだ言語は保存）。
文言は `i18n.js` にまとめています。

## 音と演出

音はすべて Web Audio API で合成しています（音声ファイルなし）。

- 室内なのでホーンは鳴らさず、会場のざわめきと **歓声・拍手**
- 体育館の床でシューズがきゅっと鳴る音、パスやバウンドの音、ネット・ポスト・キーパーのセーブの音
- レフリーの笛: プレー開始は短く「ピッ！」、反則は長く「ピーッ」
- ゴールで **紙吹雪**（花火の代わり。天井から降ってきて、ゴールの両脇のキャノンからも飛ぶ。床に積もる）
- 外すと観客のため息「あー…」

ベスト記録とナビの設定はブラウザに保存されます。

## Android アプリ

[Capacitor](https://capacitorjs.com/) でゲームのファイルをアプリに同梱し、Android アプリにしています（オフラインで遊べます）。
構成は techgymjp/jet-fighter の `docs/ANDROID_PORTING.md`、techgymjp/corner-kick と同じです。

- パッケージ名: `jp.techgym.plongeonshoot`
- アプリ名: ムササビシュート（英語の端末では Musasabi Shoot）
- 横画面固定・全画面・プレイ中は画面を消さない
- 戻るボタン: プレイ中は一時停止（ポーズ中なら再開）、遊び方の画面ではタイトルへ、タイトル・結果画面ではアプリを終了
- 別アプリに切り替えると自動で一時停止して音を止める
- シェアは Android の共有メニュー
- 広告（AdMob）
  - バナー: タイトル・遊び方・ポーズ・結果画面の下中央だけ（プレイ中は操作ボタンと重なるので出さない）
  - 全画面広告（インタースティシャル）: プレイを始める（タイトルから）、タイトルに戻る（遊び方・ポーズ・結果から）、ポーズからの再開、結果画面の「もう一度」のたびに毎回
  - リワード広告（チート）: 決まらなかった1本（セーブ・ポスト・枠外・反則）のあと「広告を見てこの1本をやり直す」（1 ゲーム 5 回まで。失敗の様子を見届けられるよう 2.2 秒後に出し、6 秒で自動的に次の1本へ）。
    最後まで見ると、その1本の成績を取り消して、同じ開始位置・キーパー・パスでもう一度（1本ごとに乱数の種をゲームの種から作って再現）。
    使ったことは結果画面とシェア文に「やり直しN回」と出る
  - EU など同意が必要な地域ではタイトル画面に「広告の設定」
- タイトル画面にバージョン（ビルド番号）とプライバシーポリシーへのリンク

ビルドは GitHub Actions（`.github/workflows/android.yml`）で行います。

1. `npm ci` → `npm run build`（`www/` に Web ファイルをコピーし、`ads-config.js` と `build-info.js` を生成）→ `npx cap sync android` → `./gradlew assembleDebug`
2. 既定ブランチなら、Release `android-latest` の `plongeonshoot.apk` を差し替え（動作確認用・テスト広告）
   - リリース画面: https://github.com/techgymjp/plongeonshoot/releases/tag/android-latest （QR コード: `docs/apk-qr.png`）
   - APK 直接: https://github.com/techgymjp/plongeonshoot/releases/latest/download/plongeonshoot.apk

   ![リリース画面の QR コード](docs/apk-qr.png)
3. GitHub Secrets に署名鍵（`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`）があれば、本番広告で署名付き AAB を作り Artifact に上げる

AdMob のアプリ ID は `android/app/src/main/res/values/strings.xml` の `admob_app_id`、本番の広告ユニット ID は `ads.js` の `UNITS.production` にあります
（本番の広告ユニットが空の種類は、本番ビルドでは出さない）。
動作確認用 APK はどれもテスト広告、Google Play 用の AAB は本番の広告です。

手元で試すとき: `npm install` → `npm run android:sync` → `npm run android:open`（Android Studio が必要）。
アイコンと起動画面は `assets/` の元画像から `npx @capacitor/assets generate --android` で生成しています。

## iOS アプリ

Android 版と同じ Capacitor のプロジェクトに `ios/` を足して作っています。構成は techgymjp/jet-fighter（JET STRIKE）の iOS 版と同じです。
Mac での作業手順（ビルド・アップロード・審査）は [`docs/IOS_BUILD.md`](docs/IOS_BUILD.md) にあります。

- Bundle ID: `jp.techgym.plongeonshoot`（Android のパッケージ名と同じ）
- iPhone 専用（iPad では iPhone 用の画面で動く）・横画面固定・全画面・プレイ中は画面を消さない
- 広告は Android と同じ出し方。AdMob では iOS を別のアプリとして登録するので、広告ユニットは `ads.js` の `UNITS.ios` に分けてある
- 起動時、広告の同意確認のあとに「トラッキングの許可」（App Tracking Transparency）の確認を出す（日英）
- シェアは iOS の共有シート

AdMob の iOS 用アプリ ID は `ios/App/App/Info.plist` の `GADApplicationIdentifier` にあります。
`.github/workflows/ios.yml` が、push のたびに Mac の環境で署名なしのビルドが通るかを確かめます。
App Store 用の画像は `docs/store/ios/` にあります。

## Claude Code から GitHub にプッシュするための設定

Claude Code（claude.ai/code）でこのリポジトリにプッシュするには、Claude と GitHub の連携が必要です。
プッシュで `403` になる場合は、次のどちらかを行ってください。

1. **Claude GitHub App をリポジトリ（組織）にインストールする**
   https://github.com/apps/claude/installations/select_target
   （`techgymjp` 組織へのインストールには、組織オーナーの権限が必要です）
2. **claude.ai 側で GitHub を再接続する**
   https://claude.ai/customize/connectors?auth_start=github&auth_start_force=1
